# Для тех, кто хочет посмотреть код

Обычный запуск и проверка задания описаны в [README](../README.md). Здесь — устройство приложения и команды для изменения кода.

## Стек

Python 3.13, FastAPI, Pydantic, SQLite из стандартной библиотеки, Svelte 5 и TypeScript. Расчёт не читает файлы и базу. Деньги считаются через `Decimal` с округлением `ROUND_HALF_UP` и уходят в интерфейс строками, чтобы браузер не терял копейки. Отдельный сервер базы ставить не нужно.

## Где что находится

| Папка | За что отвечает |
|---|---|
| `app/domain` | Товары, заявки, реквизиты, сопоставление и расчёт. Не читает файлы, не обращается к базе и интернету. |
| `app/imports` | Проверка CSV и сообщения с номером строки, названием столбца и исправлением. |
| `app/storage` | SQLite, транзакции, текущие товары, заявки и неизменяемые документы. |
| `app/documents` | Создание PDF из сохранённого снимка. Шрифты и их лицензия включены. |
| `app/web` | Команды интерфейса, проверка версии данных, загрузки и HTTP-ответы. |
| `frontend/src` | Интерфейс и подсказки на русском. Все рабочие данные получает от приложения. |
| `frontend/dist` | Готовая сборка. Она включена, чтобы проверяющему не приходилось устанавливать Node.js. |
| `tests` | Проверки расчёта, ввода, сохранения и PDF. |
| `data` | Исходные учебные CSV. |
| `var` | Локальные рабочие данные. Создаётся при запуске и не входит в архив или Git. |

Публичная точка входа каждого пакета — его `__init__.py`. Сборка живёт в `main.py`, детали — в файлах с начальным `_`. Направление зависимостей проверяется `import-linter`. В Python намеренно нет `from __future__ import annotations`: используется согласованная версия 3.13.

## Установить окружение разработчика

Нужны Python 3.13 и [uv](https://docs.astral.sh/uv/getting-started/installation/). Для изменения интерфейса также нужен Node.js, совместимый с Vite 7: например, 22.12 или новее.

В папке проекта:

```bash
uv sync --locked
uv run uvicorn app:create_app --factory --host 127.0.0.1 --port 8765
```

Приложение доступно по адресу `http://127.0.0.1:8765`. Оно раздаёт собранный интерфейс из `frontend/dist`.

После изменения интерфейса:

```bash
cd frontend
npm ci
npm run check
npm run format:check
npm run build
```

Затем обновите вкладку браузера. `npm ci` нужен при первой установке или изменении зависимостей, а не перед каждой сборкой. После изменения Python-кода перезапустите сервер либо добавьте `--reload` к команде запуска для разработки.

Версии Python-зависимостей закреплены в `uv.lock`, версии интерфейса — в `frontend/package-lock.json`. `requirements.txt` содержит только зависимости для обычного запуска. При изменении состава библиотек обновите его:

```bash
uv export --frozen --no-dev --no-hashes --format requirements-txt --output-file requirements.txt
```

## Проверить изменения

Из корня проекта:

```bash
uv run python -m pytest
uv run ruff check app tests
uv run ruff format --check app tests
uv run mypy
uv run lint-imports
```

Перед коммитом тот же контур запускает `.pre-commit-config.yaml`: ruff, формат, `uv.lock`, `requirements.txt`, import-linter и mypy. Сообщение коммита проверяет commitizen. GitHub Actions гоняет качество, тесты на Ubuntu и Windows и проверку интерфейса. Порог покрытия задан в `pyproject.toml` и поднимается только вверх.

Проверки используют временную базу. Они не удаляют рабочие записи и не требуют внешних сервисов.

Проверяются реальные риски задачи: перепутанные штуки и упаковки, повторный НДС, пустая цена и ноль, неоднозначное название, повреждённые файлы, неверные реквизиты, повторная заявка, замена прайса, конфликт двух вкладок и сохранность старого PDF после новых правок.

## Как сохраняются изменения

Загрузка проходит два шага. На первом файл проверяется полностью; результат и сам файл временно сохраняются для подтверждения на 30 минут. Рабочие товары и заявки не меняются. На втором шаге приложение применяет именно проверенный файл одной транзакцией.

У всей рабочей области есть номер изменения `revision`. Команда браузера обязана прислать номер, который пользователь видел. Если другая вкладка уже успела что-то изменить, приложение возвращает 409 и просит обновить данные. Устаревшая форма не затирает новую цену.

У нового прайса всегда новые сущности товаров, даже при совпавших артикулах. Старые сущности удаляются, ручные соответствия заявок сбрасываются. При этом сохраняются сами заявки, покупатели, выбор строк и скидки. Это согласованное упрощение тестового задания, а не модель промышленного учёта.

Заявка обновляется по `request_id`. Повтор того же файла не сбрасывает ручные решения. Изменённый файл с тем же номером заменяет строки, заново выбирает все строки и сбрасывает подбор товаров; покупатель и скидка сохраняются.

При выпуске КП сохраняются и данные расчёта, и байты PDF. Повторное скачивание возвращает тот же файл, а не новый расчёт по сегодняшним ценам. Повтор того же нажатия «Сохранить КП» передаёт заголовок `Idempotency-Key` и получает уже созданный документ. Незаконченные реквизиты и текст скидки пишутся отдельно через `PATCH /api/requests/{id}/draft` и переживают перезагрузку страницы.

Схема SQLite версионируется. Товары, заявки и документы лежат в столбцах с ограничениями. Старая база с JSON переносится при запуске. Журнал структурный: у ожидаемой ошибки есть публичный текст и отдельный текст для журнала, статус берётся у самой ошибки. Непойманный сбой отвечает JSON с кодом `INTERNAL_ERROR`.

## Как считаются суммы

Количество заявки задано в штуках. Количество единиц продажи равно количеству штук, делённому на `pack_size`; остаток от деления требует уточнения, автоматического округления вверх нет.

Для каждой подтверждённой позиции:

1. Цена из прайса уменьшается на скидку и округляется до копеек.
2. Для `net` к результату добавляется учебный НДС 20%; для `gross` НДС уже внутри цены. Цена с НДС также округляется до копеек.
3. Сумма строки равна показанной цене с НДС, умноженной на число единиц продажи.
4. Включённый НДС строки выделяется как `сумма × 20 / 120` и округляется до копеек.
5. Подытог и НДС предложения складываются из округлённых строк. Нерешённые позиции в них не входят.

Полный пример расчёта есть в README. Ставка 20% задана заданием.

## Границы безопасности и развёртывания

Входа, ролей и отдельных наборов данных нет. В формах держите вымышленные сведения.

CSV ограничен по размеру и числу строк. Проверяются содержимое, кодировка, заголовки и значения. PDF и HTML не исполняют введённый текст. Изменяющие запросы несут заголовок `X-Komplekt-Request: 1`. CORS выключен, чтобы форма с чужого сайта не ушла в приложение.

Универсальной загрузки произвольных файлов, выполнения кода и отправки КП нет. Цена из интернета не ищется. Как её отделяли бы от прайса, написано в README.

Каталог данных задаётся через `KOMPLEKT_DATA_DIR`. Обычный запуск слушает только `127.0.0.1:8765`.

## Проверка этой сборки

Автоматические проверки гоняются командой `uv run python -m pytest`. На Windows в идентификатор теста не попадает содержимое большого файла. Интерфейс после изменений собирается через `npm run build`; готовую сборку нужно положить в `frontend/dist`.
